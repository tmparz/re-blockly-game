# Advanced For 階層關卡擴充設計與評估報告

本文件針對 Blocky Easy 平台在「第四階段：進階 For 工廠」中，基於第 36 關（梳齒礦道）的難度模型，所新增的三個高難度且具備優美規律的關卡進行核心設計說明、教學價值分析與全方位專案評估。

---

## 1. 新增關卡設計詳情

為滿足玩家對於邏輯思考的挑戰，新關卡延續了「梳齒礦道」的 **雙重/巢狀 For 迴圈** 與 **路徑往返對稱** 核心特色，要求玩家尋找重複單元，以極少的方塊解決複雜的長路徑問題。

### 第一關：十字信標通道 (Cross Patrol)
*   **關卡 ID**：`adv-for-cross-patrol`
*   **地圖網格**：`7x7`，起點與終點皆在中央 `{ x: 3, y: 3 }`。
*   **設計概念**：**十字方向對稱重複**。玩家從中央出發，向北前進 3 格，收集頂端能量石後原路退回中央。在返回後，玩家需要右轉 90 度以將方向對準下一個通道，此流程重複 4 次完成。
*   **邏輯深度**：
    - 需要兩層迴圈：外層迴圈重複 4 次，內層迴圈控制前進（3次）與後退（3次）。
    - 訓練重點：方向轉換與空間中心點的對稱性，體會「返回原點再旋轉」的經典演算法。

### 第二關：城垛雙向巡檢 (Battlement Patrol)
*   **關卡 ID**：`adv-for-battlement-patrol`
*   **地圖網格**：`9x6`，起點在左下角 `{ x: 0, y: 4 }`，終點在右下角 `{ x: 8, y: 4 }`。
*   **設計概念**：**凸字形起伏波動**。模擬城堡城牆的巡視路徑（往上 2 步、右轉、往右 2 步、右轉、往下 2 步、左轉、往右 2 步、左轉）。
*   **邏輯深度**：
    - 利用 `move_forward` 重複 2 次的特徵，將複雜的城牆移動精簡成單一的大型 For 迴圈重複 2 次。
    - 訓練重點：觀察長度相同的不同方向路段，將前進與不同方向的轉向（先右轉再左轉）有機結合，是極佳的規律歸納訓練。

### 第三關：蛇形管道 (Serpentine Pipe)
*   **關卡 ID**：`adv-for-serpentine-pipe`
*   **地圖網格**：`7x7`，起點在 `{ x: 0, y: 5 }`，終點在 `{ x: 6, y: 5 }`。
*   **設計概念**：**S型曲線對稱重複**。相較於前一關，本關拉長了縱向長度（縱向需要前進 4 格），形成了大型的雙重 S 彎道。
*   **邏輯深度**：
    - 外層 For 重複 2 次，內層包含重複 4 次的前進（縱向）與重複 2 次的前進（橫向）。
    - 訓練重點：當不同路段的重複次數不同（4 次與 2 次）時，如何正確嵌套多個 For 迴圈以優雅解決，能有效防範學生盲目堆疊方塊的壞習慣。

## 2. 全方位專案與工程評估 (Rule 5)

依照資深全端工程師與專業專案經理標準，針對此次關卡擴充的評估如下：

### ① 商業與教育價值 (High)
*   **教學平緩度**：原第四階段在「梳齒礦道」之後，難度曲線出現陡升。新增這三關，在同樣的難度區間提供更多元、更多維度的規律實踐（十字對稱、凸字起伏、S型折返），能加深小朋友對巢狀 For 迴圈的肌肉記憶。
*   **使用者體驗**：高難度的關卡能顯著提升高年級或學習較快學生的成就感，並作為課堂中的「挑戰關卡」供教師做差異化教學。

### ② 技術可行性 (Excellent)
*   **完全相容**：此擴充僅需在 `app.js` 的 `LEVELS` 陣列中靜態注入三個 JSON 配置，完全不需要修改核心遊戲引擎、Blockly 自訂積木或地圖渲染邏輯。
*   **無額外負載**：零第三方依賴，純前端解析，對載入速度無任何負面影響。

### ③ 開發與維護成本 (Very Low)
*   **開發成本**：極低。透過複用現有的座標、牆壁、寶石與 Blockly 元件機制即可完成。
*   **維護成本**：極低。關卡配置為純宣告式（Declarative），未來若要調整地圖或步數限制，只需編輯 JSON 物件即可，無任何邏輯程式碼維護成本。

### ④ 資安風險 (Zero)
*   **客戶端純靜態執行**：本專案所有程式執行皆在瀏覽器沙盒中完成，沒有後端資料庫交互與敏感 API 調用，零資安與滲透風險。

### ⑤ 擴充性 (High)
*   **鬆耦合架構**：`LEVELS` 的設計極具擴充性，未來若想引入更多新關卡，可直接在陣列中以相同格式進行推入，或將 `LEVELS` 拆分出獨立的 `levels.js` 設定檔進行完全離線化的管理。

### ⑥ 測試與驗證難度 (Medium)
*   *考量點*：高難度關卡的牆壁與通道配置極其複雜，稍有不慎容易造成坐標錯位而產生「鬼牆」或死胡同。
*   *驗證手段*：
  1. 專案中內建了 `solution` 自動驗證機制。
  2. 已在 `app.js` 的新關卡中完整配置了正確的 Blockly 抽象語法樹 (AST) 解決方案。
  3. 建議在本地瀏覽器實際手動跑一次示範，確保小隊員不會撞牆。

### ⑦ 上線與部署風險 (Low)
*   由於此專案為 Cloudflare Pages 靜態網站，新程式碼若有語法錯誤（如 JSON 逗號遺漏），將在 build 時被 Node.js 拋出。
*   已成功通過本地打包命令 `npm run build`，確保語法完全正確。
