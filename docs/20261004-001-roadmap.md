## 階段 A：讓第三階段能在教室完整上完（優先，約 2–3 次開發）

### A1. 作品分享與改編（分享碼／QR code）
- **為什麼**：第三階段第 15 週的改編活動、CSTA 1B-AP-12（改編）、1B-AP-14（標示出處），目前完全做不到；第二階段「同學試玩」也只能用同一台 iPad。
- **做什麼**：
  - Story Lab 加「📤 分享」：把 workspace JSON 壓縮後放進網址 hash（`story.html#share=...`），並顯示 QR code（純前端，不需要後端）。
  - 分享時填「作者名字」（下拉選單選座號，或用 iPad 鍵盤打一次名字）。
  - 打開分享連結時進入「改編模式」：作品標題下面固定顯示「改編自：○○ 的作品」，再分享時自動帶上原作者鏈（最多 3 代）。
  - 「我的遊戲／我的產品／我的故事」的檢查表加一項「📝 標示了原作者（改編作品才需要）」。
- **完成標準**：兩台 iPad 掃 QR code 就能互相打開、改編、再分享；網址長度在 QR code 可以掃的範圍內（大約 2,000 字元以內，超過要先壓縮）；測試涵蓋「編碼 → 解碼 → 跟原本的 workspace 一樣」。
- [x] 完成（commit：`1d90644`）。分享碼去掉積木 id 後用 deflate 壓縮，最大範例連結 857 字元、大型作品約 1,150 字元；檢查表的「標示原作者」做成只在改編作品出現的目標：角色要說出原作者的名字。

### A2. 老師使用說明更新 + 不插電活動卡
- **為什麼**：老師拿到網站，不知道 Quest Lab 和 Story Lab 怎麼帶、第三階段怎麼排課。
- **做什麼**：

  - 新增 `unplugged.html`：可以列印的不插電活動卡（點餐機、身高門、兩個盒子、排隊的盒子、俄羅斯娃娃……），一張 A4 兩張卡。
  - 新增 `answers.html`（老師用）：從 `UNITS` 自動產生每關的解答積木圖和一句說明，不用手寫。
- **完成標準**：老師只看這三頁，就能帶完任何一週的課。
- [x] 完成（commit：`9481e19`）。解答頁用一個隱藏的 Blockly 工作區依序畫出 112 關的解答，再把 SVG 複製到每張卡片；不插電活動卡共 10 張。

### A3. Blockly 畫面自動測試（Playwright）
- **為什麼**：目前 15 種 Quest 進階積木、8 種 Story 遊戲積木，都只能靠人工在瀏覽器驗收。

- [x] 完成（commit：`7f7d38b`）。用 `playwright-core` 加上電腦已安裝的 Chrome，不另外下載瀏覽器；全部跑完約 2 分鐘。改壞一關的解答來測試，確認會被抓到。

## 階段 B：學習支援（約 3–4 次開發）

### B1. 逐步執行與變數追蹤表（Quest Lab）
- **為什麼**：除錯、追蹤變數是三、四年級最弱的能力；第三階段的多個變數、串列、遞迴更需要。
- **做什麼**：
  - 控制列加「⏭ 一步」按鈕：每按一下走一個 frame，正在執行的積木會高亮（引擎的 frames 已經有積木 id）。
  - 地圖下方可以展開「📋 追蹤表」：每一步一列，欄位是每個變數和串列（frames 已經記錄 `vars` 和 `list`）。
  - 遞迴關卡顯示目前的呼叫深度（例如「🌀 第 3 層」）。
- **完成標準**：第三階段任一關，都能一步一步看到變數怎麼變，追蹤表和地圖上的數字一致。
- [x] 完成（commit：`7fb4da4`）。執行到一半按「一步」會暫停，再按「執行」會接著跑完；追蹤表只顯示已經走過的步驟，方便學生先預測；遞迴關卡另外顯示「🎛️ 輸入」那一欄，看得到數字一層一層變小。

### B2. 「猜猜看」預測任務
- **為什麼**：讀程式、預測結果是銜接文字程式的重要能力，也很適合當形成性評量。
- **做什麼**：新的任務類型 `mode: "predict"`：程式已經寫好、不能改，學生先從選項裡選「Robo 會說幾？」或「會停在哪一格？」，再按執行對答案。每個第三階段單元的開頭和結尾各加 1–2 關。
- **完成標準**：每個第三階段單元至少 2 關預測任務；答錯時會顯示追蹤表，讓學生看出是哪一步想錯了。
- [x] 完成（commit：`b06004f`）。第三階段 6 個單元各加 2 關（開頭、結尾各 1），共 12 關。正確答案由引擎實際跑出來，測試會檢查剛好只有一個選項是對的。猜猜看的關卡顯示 🔮、不佔關卡編號，課程頁上的「第 N 關」連結都不用改。

### B3. 全班進度（不需要後端）
- **為什麼**：老師需要知道誰卡在哪一關。
- **做什麼**：
  - 學生頁面加「📊 我的進度碼」：把星星壓縮成短碼並顯示 QR code。
  - `teacher.html`：老師用 iPad 一個一個掃，或貼上進度碼，產生全班表格（學生 × 單元，顯示星星、卡最久的關卡），資料只存在老師自己的瀏覽器，可以匯出 CSV。
- **完成標準**：30 位學生在 5 分鐘內收完進度；不需要帳號，也不會把資料傳到任何伺服器。
- [x] 完成（commit：`568b369`）。QR code 裡放的是 `teacher.html#p=…` 網址，老師用 iPad 內建相機掃描就會加進表格，網頁本身不需要掃描功能。「卡最久的關卡」是指還沒過、按執行失敗最多次的那一關（從這版開始記錄失敗次數）。

## 建議順序

```
A1 分享與改編 ─┐
A2 老師說明    ├─→ 第三階段可以完整上課
A3 畫面自動測試 ┘
        ↓
B1 逐步執行 → B2 預測任務 → B3 全班進度
        ↓
C1 文字與條件事件（C2 選做）
        ↓
D1 程式碼對照 → D2 改數字 → D3 寫 Python → D4 第四階段課程頁
```

**原則**（延續到目前為止的做法）：
1. 每關只多一個新觀念，用 🟢🟡🔴 分級；新觀念盡量用「起始程式故意寫錯」來教。
2. iPad 優先：下拉選單、點一下就接上，不需要打字（D3 例外）。
3. 每個新功能都要有 `npm run check` 涵蓋的測試；畫面相關的功能等 A3 做好後也要加進瀏覽器測試。
4. 不需要帳號、不需要後端，資料只存在使用者自己的瀏覽器或分享碼裡。
5. 單一檔案不超過 300 行。
